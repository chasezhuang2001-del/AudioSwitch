工作原理

1. 连接状态检测 — 双层机制

主检测:COL02 RACE 链路指示 (秒级)
通过 SetupAPI 枚举 dongle 的 HID 集合,30ms 轮询捕获链路状态指示帧:LINK UP → 连接,LINK DOWN → 断开。dongle 在链路变化瞬间主动推送,实测延迟 1-3 秒。

备份检测:COL04 电量查询 (兜底)
每 2s 发送 CC 12 07,响应第 6 字节 = 电量;超时/无效值 = 断开。连续 3 次确认翻转,覆盖 LINK 指示缺失的异常场景。连续 5 次失败自动退避 (2s→10s),防止 dongle 卡死。

⚠️ 为什么不用系统端点状态:耳机关机时 Windows 音频端点仍显示 Active,快照完全一致,无法区分。

2. 设备切换

pycaw + comtypes 调用 IPolicyConfig COM 接口,同时设置 console / multimedia / communications 三角色默认播放设备。手动切换保护:检测到默认设备偏离期望且非守护所为 → 暂停干预,耳机状态翻转时自动恢复。

3. 托盘图标

pystray + Pillow 动态渲染 32×32 图标 (系统缩放到槽位),电量数字自动适配字号;断开时按配置隐藏或显示灰 ✕。

调试设备切换时遇到的问题

  1. 端点状态不可靠:耳机关机后音频端点仍 Active → 改用 HID 厂商协议查询 + RACE 链路指示
  2. 查询信号静默:部分状态变化不产生 HID 报告 → 双通道冗余 + 连续 3 次确认防误判
  3. dongle 高频查询卡死:返回 0xAA 且 LINK 消失 → 自动退避 (2s→10s),必要时重插 dongle
  4. COM 未初始化:多线程下 comtypes 状态不一致抛 CO_E_NOTINITIALIZED → CoInitializeEx 显式初始化

How It Works

1. Connection detection — dual-layer

Primary: COL02 RACE link indication (seconds)
Enumerates the dongle's HID collections via SetupAPI, polls every 30ms for link-state frames: LINK UP → connected, LINK DOWN → disconnected. The dongle pushes indications instantly; measured latency 1-3s.

Backup: COL04 battery query (safety net)
Sends CC 12 07 every 2s; response byte 6 = battery %; timeout/invalid = disconnected. 3 consecutive confirms flip the state, covering missing link indications. 5 consecutive failures trigger backoff (2s→10s) to avoid hanging the dongle.

⚠️ Why not endpoint state: the Windows audio endpoint stays Active after power-off — snapshots are identical, cannot distinguish.

2. Device switching

pycaw + comtypes call the IPolicyConfig COM interface, setting console / multimedia / communications roles simultaneously. Manual-switch protection: deviation not caused by the daemon sets user_suppress; auto-resumed on headset state flip.

3. Tray icon

pystray + Pillow render a 32×32 icon (system-scaled to slot), digit auto-fits; hidden or grey ✕ per config when off.

Issues While Debugging Device Switching

  1. Unreliable endpoint state: endpoint stays Active after power-off → moved to HID vendor protocol + RACE link indication
  2. Silent query signals: some changes produce no HID report → dual-channel redundancy + 3-consecutive-confirm
  3. Dongle hang from frequent queries: returns 0xAA with link gone → automatic backoff (2s→10s); replug to recover
  4. COM not initialized: multi-threaded comtypes divergence throws CO_E_NOTINITIALIZED → explicit idempotent CoInitializeEx
